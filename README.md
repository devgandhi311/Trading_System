# NIFTY50 Trading

Python 3.11+ trading research and execution scaffold for NIFTY-style strategies. The project is built around safe defaults: paper trading is the default, live trading is disabled unless explicitly enabled, and credentials are never stored in code or YAML.

## Risk Warning

Trading options and leveraged instruments can cause rapid financial loss. This software is for research, backtesting, and controlled paper trading unless you have independently reviewed, tested, and accepted the operational risk. Live trading must remain disabled by default.

## Folder Structure

- `backtesting/` - backtest engines, simulation, and historical replay.
- `broker/` - broker adapters and paper broker integrations.
- `config/` - YAML configuration for settings, broker defaults, risk limits, strategies, and instruments.
- `dashboard/` - Streamlit or reporting UI components.
- `data/` - local market data, cache, and generated datasets.
- `execution/` - order routing and execution orchestration.
- `features/` - feature engineering code.
- `logs/` - runtime logs generated by `utils.logger`.
- `market/` - market data ingestion and normalization.
- `ml/` - machine learning training, inference, and model utilities.
- `models/` - shared enums and dataclasses used across the system.
- `news/` - financial news providers, cleaning, sentiment, event-risk detection, caching, and reports.
- `pricing/` - option pricing and analytics.
- `regime/` - market regime detection.
- `reports/` - generated trade, risk, and performance reports.
- `risk/` - risk checks and position controls.
- `strategies/` - strategy implementations.
- `tests/` - pytest test suite.
- `utils/` - config loading, logging, time, file, math, and exception helpers.
- `main.py` - safe startup entrypoint that initializes config and logging only.

## Setup

Create and activate a virtual environment:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Run tests:

```powershell
python -m pytest
```

Start the safe initialization entrypoint:

```powershell
python main.py
```

`main.py` loads configuration and initializes logs. It does not start live trading.

## Command Examples

Run safe initialization:

```powershell
python main.py init
```

Run a sample backtest and write an Excel report:

```powershell
python run_backtest.py --sample --rows 180 --report-dir reports/backtests
```

Run the PAPER smoke workflow and write dashboard state files:

```powershell
python run_paper.py --state-dir data/live
```

Start the read-only dashboard:

```powershell
streamlit run dashboard/app.py
```

Run LIVE preflight only:

```powershell
python run_live.py
```

The LIVE preflight does not place orders. With the default config it is expected to block.

## Configuration

Configuration lives in `config/`:

- `settings.yaml` - mode, live-trading switch, market timings, timezone, logging, data paths, and report paths.
- `risk_limits.yaml` - capital, daily loss controls, trade limits, margin, slippage, spread, order timeout, and emergency exit policy.
- `strategy_config.yaml` - enabled strategies, expiry type, confidence threshold, regimes, lot sizes, and sizing.
- `broker_config.yaml` - broker-level non-secret settings only.
- `instruments.yaml` - tradable instrument metadata.

Load config in code:

```python
from utils.config_loader import ConfigLoader

config = ConfigLoader().load()
print(config.settings.mode)
```

## .env Format

Secrets must come from `.env` only. Do not put credentials, API keys, tokens, passwords, TOTP seeds, or client secrets in source files or YAML.

Example `.env`:

```dotenv
KOTAK_API_KEY=replace_me
KOTAK_USER_ID=replace_me
KOTAK_MOBILE=replace_me
KOTAK_MPIN=replace_me
KOTAK_TOTP_SECRET=replace_me
FINNHUB_API_KEY=replace_me
ALPHA_VANTAGE_API_KEY=replace_me
MARKETAUX_API_KEY=replace_me
```

Read secrets with:

```python
from utils.config_loader import ConfigLoader

loader = ConfigLoader()
api_key = loader.get_secret("KOTAK_API_KEY")
```

Kotak credentials are never hardcoded. Keep them in `.env`, keep `.env` out of version control, and rotate credentials immediately if they are exposed.

News API keys are also loaded from `.env` only. Finnhub is the primary provider, with Alpha Vantage and Marketaux used as backups when configured. Do not place news keys in YAML files or source code.

`broker.kotak_auth.KotakAuth` loads these variables, generates TOTP with `pyotp`, and stores session tokens in memory only. Real Kotak SDK/API calls are isolated behind an adapter so credentials and tokens are not printed or persisted.

`broker.order_manager.OrderManager` validates every `OrderRequest`, logs order intent before execution, and simulates orders in `PAPER` and `BACKTEST`. Live order routing is blocked unless config is explicitly set to `mode: LIVE` and `live_trading_enabled: true`. Market orders are rejected except for emergency exits when risk config permits them.

`execution.order_pricing` and `execution.order_validator` enforce safe order pricing before broker routing. Option-selling entries use LIMIT orders, short-option profit booking uses LIMIT BUY, stop-loss exits use BUY SL-LIMIT with trigger plus buffer, and MARKET is reserved for emergency exits only when `emergency_market_exit_allowed` is true.

`execution.ExecutionEngine` coordinates approved `StrategyPlan` execution: it validates legs, re-checks risk, checks margin, prepares entry LIMIT baskets, routes orders, cancels timed-out unfilled orders, squares off partial fills, places SL-LIMIT stop-loss and LIMIT profit-booking exits, monitors P&L, and exits on target, stop loss, regime change, time exit, kill switch, daily loss, or manual squareoff. LIVE routing remains blocked unless `mode: LIVE`, `live_trading_enabled: true`, risk approval, margin approval, and order validation all pass.

`execution.LatencyMonitor` tracks live tick receipt, feature update, regime detection, ML prediction, strategy selection, risk validation, margin validation, order API request, exchange acknowledgement, and total decision-to-order time. It rejects delayed scalping trades, reduces confidence for slow decisions, logs warnings, and writes daily latency reports to `reports/risk_reports/`.

`broker.websocket_feed.WebSocketFeed` manages subscriptions, heartbeat tracking, reconnect disconnect counts, latest-tick persistence under `data/live/latest_ticks.json`, and callback delivery on every tick. Real Kotak WebSocket syntax is isolated behind an adapter; `PAPER` and `BACKTEST` use safe mock ticks and trigger a kill switch when disconnects exceed the configured threshold.

`market.instrument_master.InstrumentMaster` downloads or mock-loads broker instruments into `data/raw/broker_downloads/` and supports lookup by symbol, token, underlying, expiry, strike, and option type. `market.option_chain.OptionChain` builds and saves NIFTY/BANKNIFTY option-chain snapshots with ATM, ITM, OTM, nearest expiry, monthly expiry, and custom expiry helpers.

`market.data_loader.DataLoader` loads long-horizon NSE files from `data/raw/nse_30_years/`, auto-detects OHLCV columns, removes invalid rows and duplicates, saves cleaned data through `DataStore`, and writes `reports/risk_reports/data_quality_report.xlsx`. `market.data_preprocessor.DataPreprocessor` normalizes dates, fills missing business days, adjusts corporate-action-like anomalies, normalizes volume, and creates continuous index-level datasets.

`market.market_data_manager.MarketDataManager` unifies historical data, live ticks, broker quotes, and option-chain snapshots. `BACKTEST` mode reads historical closes, `PAPER` mode can use mock ticks, and `LIVE` mode routes quote access through the broker client.

Return and volatility feature generators live in `features/returns.py` and `features/volatility.py`. They add daily/log/gap/intraday returns, rolling statistics, ATR, realized/Parkinson/Garman-Klass volatility, distribution features, expected move, gap probabilities, and upside/downside averages, then save outputs to `data/features/`.

Microstructure and smart-money context features live in `features/microstructure.py` and `features/smart_money.py`. They are intended only for regime detection, prediction confidence, and filtering. They must not be treated as direct buy/sell triggers.

`features.feature_pipeline.FeaturePipeline` combines statistical, volatility, microstructure, and smart-money context features, avoids look-ahead by computing pattern context only from data available up to each row, caches outputs in `data/features/`, and writes a feature summary report.

## News Integration

Financial news support lives in `news/` and is configured by `config/news_config.yaml`. `NewsFetcher` uses Finnhub first, then Alpha Vantage and Marketaux as fallbacks. `NewsCleaner` removes duplicates and tags relevant topics, `NewsSentiment` creates a bounded sentiment score, and `EventRiskDetector` converts headlines into LOW, MEDIUM, HIGH, or EXTREME event-risk levels.

To use Finnhub, create an API key from Finnhub and add it to `.env`:

```dotenv
FINNHUB_API_KEY=your_key_here
```

Optional backup keys:

```dotenv
ALPHA_VANTAGE_API_KEY=your_key_here
MARKETAUX_API_KEY=your_key_here
```

News is advisory and protective only. It can adjust prediction confidence, add `news_sentiment_score` and `event_risk_score` to features, reduce position size during MEDIUM risk, and block new trades during HIGH or EXTREME risk. It must not be used as a direct buy or sell trigger.

In PAPER and LIVE modes, news is fetched on the configured interval, 15 minutes by default, and cached under `data/news_cache/`. The system does not call news APIs on every tick. If all providers fail, the default behavior is to log a warning and use neutral news risk unless `fail_safe_block_on_news_api_error` is enabled in `config/news_config.yaml`.

In BACKTEST mode, live news fetching should stay disabled. Backtests either ignore the news filter or use cached historical news only, with timestamps aligned so future headlines cannot leak into earlier decisions.

`backtesting.BacktestEngine` runs historical NSE backtests with feature pipeline integration, regime detection, optional ML prediction, strategy simulation, option payoff approximation, transaction costs, slippage, limit-fill assumptions, SL-LIMIT and target simulation, expiry payoff, walk-forward validation, and Excel reports. Metrics include total return, CAGR, max drawdown, win rate, average profit/loss, expectancy, profit factor, Sharpe, Sortino, Calmar, losing streak, VaR, CVaR, and strategy/regime P&L.

`reports.ReportGenerator` writes trade-level and daily reports. Trade reports include execution, P&L, regime, ML, risk, Greeks/IV, liquidity, mistake, improvement, and latency fields. Daily reports summarize trades, P&L, drawdown, loss usage, best/worst trades, regime/strategy performance, mistakes, and next-day improvement notes. `dashboard/app.py` is a read-only Streamlit dashboard for current regime, predictions, positions, daily P&L, risk usage, active orders, latency, trade logs, and kill switch state.

Option pricing helpers live in `pricing/`. They include Black-Scholes call/put pricing, Greeks, implied volatility solving with Brent's method, IV rank/percentile, probability ITM/OTM, and expected move from IV.

`ml.dataset_builder.DatasetBuilder` creates supervised targets from cached feature data without look-ahead bias and writes model datasets to `data/model_data/`. Training modules in `ml/` use walk-forward validation, save metrics and feature importance to `reports/model_reports/`, save models through `ModelRegistry`, and skip optional packages such as XGBoost, LightGBM, HMM, or GARCH tooling when unavailable.

`ml.prediction_engine.PredictionEngine` combines latest features, current regime, and option-chain context into an advisory `PredictionResult` with probabilities, expected range, confidence, warnings, and explainability. `strategies.strategy_selector.StrategySelector` converts approved predictions into advisory `StrategyPlan` objects only. Neither module places orders.

Option strategy builders in `strategies/` include iron condor, credit spreads, debit spreads, long gamma, and short strangle. They calculate advisory legs, max profit, max loss, breakevens, targets, stops, entry reasons, exit conditions, and placeholder margin estimates. `ShortStrangleStrategy` is disabled by default, is not listed in default allowed strategies, and requires emergency hedge logic before it can return sell legs.

`risk.RiskManager` is the central pre-execution gate. It checks daily loss, daily profit lock, per-trade max loss, trade count, open positions, consecutive losses, margin usage, bid-ask spread, slippage, event-risk regimes, market hours, no-new-trade cutoff, defined strategy max loss, and kill-switch state. It returns a `RiskDecision` with approval status, rejection reason, allowed quantity, max risk amount, risk used, warnings, and detailed check results.

## Trading Modes

`BACKTEST` mode is for historical simulation. It should use historical data, simulated fills, and report outputs only.

`PAPER` mode is the default. It allows strategy, risk, and execution flows to run against simulated broker behavior without placing real orders.

`LIVE` mode is intentionally gated. To enable it, `config/settings.yaml` must be deliberately changed to:

```yaml
mode: LIVE
live_trading_enabled: true
```

Live mode also requires a valid broker session, risk approval, margin approval, order validation, and an inactive kill switch before any live order path can be used.

News event risk is part of the live safety gate. HIGH or EXTREME event risk blocks new entries, and MEDIUM event risk can reduce position size.

## Safety Warning

Do not connect a live broker execution adapter until BACKTEST and PAPER reports have been reviewed, order prices are reconciled with broker contract notes, kill-switch behavior has been tested, and position sizing has been independently checked. Kotak credentials must remain in `.env`; never hardcode credentials or tokens.

## Troubleshooting

- Config fails to load: check every YAML file under `config/` and keep broker secrets out of YAML.
- `run_live.py` is blocked: this is expected unless `mode: LIVE`, `live_trading_enabled: true`, valid `.env` credentials, a real Kotak adapter, and all risk gates are present.
- Backtest has no NSE files: use `python run_backtest.py --sample` or place CSV/XLSX/Parquet data in `data/raw/nse_30_years/`.
- Dashboard is empty: run `python run_paper.py --state-dir data/live` or generate reports first.
- News stays neutral: verify `FINNHUB_API_KEY` in `.env`, check `config/news_config.yaml`, and inspect `logs/system.log` for provider fallback warnings.
- Import errors for optional ML packages: optional models are skipped when packages such as XGBoost, LightGBM, HMM, or GARCH tooling are not installed.
- Report files not created: ensure the process can write under `reports/`, `data/`, and `logs/`.
